# Working agreement

Do not begin implementation unless the user explicitly asks you to implement.
Otherwise, summarize proposed actions or create requested OpenSpec planning artifacts.

Use OpenSpec for changes to project behavior.
Read `openspec/config.yaml` and the selected change before work.
Keep proposals under `openspec/changes/` until implementation and validation are complete.
Do not treat a proposal or successful specification validation as implementation approval or runtime evidence.

Keep the first milestone small. Do not select a service framework or database without an accepted design.
Do not provision cloud resources, publish a repository, or push changes unless the user authorizes that action.

Labs contain switches only. Never introduce CloudVision or host containers.
Anonymize the example fabric and leave all reference repositories unchanged.
Do not copy credentials, customer data, or generated reference artifacts.

Keep the MLAG investigation separate from the bootstrap.
Do not install the experimental firewall workaround or claim its suspected cause is proven.
Require MLAG coverage when accepting the digital twin workflow.
